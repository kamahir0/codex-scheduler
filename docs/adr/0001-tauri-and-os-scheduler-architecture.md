# ADR 0001: Tauri 2 と OSスケジューラによるヘッドレス実行アーキテクチャ

Status: Approved

## 背景（Context）

AIコーディングツールの利用枠枯渇時に、深夜のリセット時刻に合わせてセッションを自動再開させたい。
しかし、一般的なデスクトップアプリやWebアプリがタイマーで待機する設計だと、就寝中のPCスリープやアプリの誤終了によってジョブが実行されず失敗するリスクが高い。
また、ブラウザアプリではローカルCLIの直接起動が制限されている。

## 決定（Decision）

1. アプリケーション基盤として **Tauri 2 (Rust + Webフロントエンド)** を採用する。
2. アプリ自身を深夜まで常駐させるのではなく、**OSネイティブのスケジューラ（macOS: `launchd`, Windows: `Task Scheduler`）** にジョブを委譲する。
3. 実行主体として、独立した軽量CLI worker（`codex-scheduler-cli run-job <job_id>`）を呼び出す構成とする。
4. ジョブ管理とビジネスロジックは共有コアクレート `codex-scheduler-core` に集約し、CLIとTauriバックエンドから同一のセマンティクスを共有する。

## 結果（Consequences）

- **メリット**:
  - ユーザーはジョブを登録したらアプリを閉じて就寝できる。
  - OSネイティブのスケジュール機構により、スリープ復帰時や指定時刻のトリガーが確実に動作する。
  - メモリ消費が極めて小さく、バックグラウンドでの不要なリソース消費がない。
  - CLIとGUIでコードが完全に共通化される。
- **トレードオフ**:
  - macOSの `launchd` plist生成やWindowsの `schtasks` コマンド呼び出しなど、プラットフォーム固有のスケジューラ登録処理が必要。

## 代替案（Alternatives）

- **アプリ常駐（setTimeout / sleep）**: PCスリープやアプリ終了でタスクが消失するため不採用。
- **Electron**: メモリ・ディスクフットプリントが過大であり、小型ユーティリティに不相応なため不採用。
- **純粋なWebサービス + クラウドエージェント**: ローカルソースコードやセッションDBへの直接アクセスが困難でセキュリティリスクがあるため不採用。
