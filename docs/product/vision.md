# プロダクトビジョン（Product Vision）

Status: Approved

`codex-scheduler` は、AIコーディングツール（主にOpenAI Codex、将来的にClaude Code等を拡張可能）における利用枠（Quota / Rate Limit）枯渇時に、制限リセット時刻（深夜帯など）に合わせて外部から自動でプロンプト（`continue` 等）を送信・再開し、翌朝同一セッションで作業を継続できるようにする、ローカルファーストのスケジュール管理ツール（Desktop GUI版および独立したstandalone CLI版）である。

## Product problem / motivation

AIコーディングエージェントを使った開発では、作業途中でトークン制限や利用枠の上限に到達してセッションが停止することが頻繁に発生する。
利用枠のリセットは深夜（例: 02:00 等）に来ることが多く、開発者は就寝前に「リセットされたら続きをやらせておきたい」と望む。
しかし：
1. **トークン枯渇後の制限**: 利用枠が尽きた状態では、チャット画面内から予約タスク（Scheduled Tasks等）を新規作成することができない。
2. **Desktop-firstの維持**: 普段デスクトップアプリ（GUI）で作業しているユーザーは、CLIだけで完結するワークフローではなく、夜間はアプリを閉じておき、翌朝デスクトップアプリを開いた時に**同一セッションで作業が継続していること**を求める。
3. **PCスリープ・アプリ常駐の脆さ**: アプリのタイマー（`setTimeout` やアプリ常駐）に依存すると、PCスリープやアプリ終了でジョブが実行されない。
4. **Quota判定とリトライ**: リセット予定時刻ジャストに実行しても、数分の遅延や内部同期ずれで `Quota exceeded` になる場合があるため、知的なリトライが必要。

これらを解決し、**「設定して寝れば、朝には作業が進んでいる」** 体験を堅牢に提供する。

## Product direction

- **Tauri 2 による軽量・堅牢なクロスプラットフォーム（macOS / Windows）デスクトップアプリ**。
- **Ant Design (antd) によるモダンで洗練されたUI**:
  - クリーンで視認性の高いテーブル、フォーム、ステータスタグ、実行進捗、ログ確認。
  - ダークモード / ライトモード対応。
- **OSネイティブスケジューラ連携**:
  - アプリ自身が深夜まで常駐するのではなく、OSのスケジューラ（macOS: `launchd`, Windows: `Task Scheduler`）に登録し、アプリを落としても確実に実行されるアーキテクチャ。
- **Provider Adapter構造**:
  - まずは要件に完全に合致する **Codex** を第1級市民として実装。
  - 将来的に他ツール（Claude Code等）を追加可能な拡張境界を保持。
- **Quota検知 & リトライポリシー**:
  - 失敗理由が利用制限超過の場合、指定間隔（例: 5分）で再試行する機構。

## Scope discipline / 何を作らないか

- **クラウド常駐サーバ**:
  - 本ツールはローカルファーストなDesktop Utilityであり、外部サーバーやクラウドへのユーザーコード・認証情報の送信は行わない。
- **AIチャットクライアント自体の再実装**:
  - 本ツールは「スケジューラ」であり、Codexデスクトップアプリそのものを置き換えるチャットUIは作らない。
- **無意味な独自フレームワーク**:
  - プラグイン機構や複雑な設定ファイルは作らず、Core + Adapter + Tauri IPC + OS Scheduler の明快な構成を守る。

## 成功条件

- ユーザーがSession ID、作業ディレクトリ、再開時刻、プロンプトを入力して「スケジュール」を押すだけでジョブが登録できる。
- アプリを終了しても、指定時刻にOSによってworkerが起動され、`codex exec resume <session_id> "continue"` が正常に実行される。
- 翌朝ユーザーがCodexデスクトップアプリを開いたとき、プロンプトが実行されてセッションが継続している。
- 実行ログやリトライ履歴がアプリ上のAnt Designテーブルで明確に確認できる。
